# vesta-design-doc

写技术方案的 skill。管三件事：**写成什么结构**、**话怎么说**、**写完怎么查**。

## 安装

```
/plugin marketplace add jupiter-eng/vesta-claude-plugins
/plugin install vesta-design-doc@vesta
```

## 用起来

自动触发，不用记命令：

```
写一份用量上报的技术方案
这份方案帮我看看，有哪些要优化的
太啰嗦了，帮我精简一下
```

两种模式自动判断：

| 说法 | 做什么 |
|---|---|
| 写一份 / 起草 / 新建 | **起草**——按骨架建文档，边写边按规范组织 |
| 帮我看看 / review / 精简 | **审阅**——按清单逐条过，分 P0/P1/P2 输出，每条指到具体位置 |

## ① 结构

章节顺序对应评审时的提问顺序：**为什么做 → 整体长什么样 → 怎么实现 → 怎么验证 → 谁做多久**。

三条容易漏但很管用的约定：

- **负责人写在节标题上**（`3.1 SDK 设计 张三`）——评审第一个问题永远是「这块谁负责」
- **「非本期范围」单独成节且写理由**——评审最常见的争议是「为什么不做 X」
- **完整配置进附录**，正文留要点——正文给决策者看，附录给实施者看

模板在 `skills/tech-design-doc/assets/template.md`。

## ② 表述

结论先行 · 能用表就不用段落 · 一句话一个事实 · 删掉铺垫词 · 数字要有出处。

用图给的是**判断标准**，不是鼓励用图：

| 情况 | 用什么 |
|---|---|
| 数据流经 3 个以上组件 | 流程图 |
| 同一事物在不同阶段形态不同 | 分阶段图 |
| 多条并行线有依赖 | 依赖图 |
| 两个东西对比 | **表格，别画图** |
| 线性 2–3 步 | **列表，别画图** |

四组真实改写对照（前后对比 + 为什么这么改）在 `skills/tech-design-doc/references/examples.md`，按需加载。

## ③ 自检

按严重度分三档，先报 P0：

| 档 | 查什么 |
|---|---|
| **P0** 事实错误 | 同一事实两处写法不一致、口径不一致、配置依赖的前提被删掉 |
| **P1** 前后不一致 | 数量词与实际不符、指代失效、交叉引用悬空 |
| **P2** 影响评审 | 验收用样板对象、空壳章节、缺「建成之后长什么样」 |

这份清单来自真实文档的评审记录。
